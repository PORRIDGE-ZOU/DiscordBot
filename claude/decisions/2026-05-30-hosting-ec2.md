# Hosting: existing AWS EC2 instance (Amazon Linux 2023)

**Date**: 2026-05-30
**Decided by**: George
**Status**: Active

## Context
Bot needs to stay online when George's laptop is off. Wanted free or very cheap.
No Raspberry Pi. Initially explored Oracle Cloud Always Free; mid-discussion George
surfaced an existing EC2 `t3.micro` (Amazon Linux 2023, us-east-2) already running a
daily Steam-scraper job.

## Decision
Host the bot on the existing EC2 instance, alongside the scraper, under a systemd
service (`qlpbot`). $0 marginal cost. See docs/howtos/deploying-on-ec2.md.

## Alternatives Considered
- **Oracle Cloud Always Free** — genuinely free, beefier (ARM 24GB), but new account
  + signup + `Out of host capacity` provisioning hassle. Set aside once the EC2 box
  appeared (already provisioned, $0 marginal).
- **Fly.io (~$2/mo)** / **Hetzner (~€4/mo)** — smooth but cost money for no benefit
  over the existing box.
- **Render/Replit free** — sleep on idle; disqualified for a gateway bot.
- **New EC2 instance** — pointless extra box/cost; reused the existing one + its key.

## Consequences
- **Shared 1 GB RAM** with a memory-heavy daily scraper. Mitigated with a 2 GB swap
  file + `Restart=always`. If the bot restarts around scrape time, escalate to
  t3.small (paid) or a separate free Oracle box.
- **Shared 8 GB disk** (~47% used at setup). Scraper stores everything → disk growth
  is the main long-term risk; full disk breaks both. Watch `df -h /`.
- Public IP changes on instance stop/start (no Elastic IP) → update ssh/rsync host.
- Transcription (faster-whisper large-v3) will NOT run here — too heavy. Stays the
  "host light bot here, transcribe off-box" split. GPU/CPU question still open.
- Deploy loop: rsync from Mac → `systemctl restart qlpbot`. One token = one instance;
  never run the bot locally while EC2 serves.
